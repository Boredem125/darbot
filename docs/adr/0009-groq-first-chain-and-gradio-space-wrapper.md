# ADR-0009: Groq-first LLM chain; HF Space runs a Gradio-SDK wrapper

- Status: Accepted
- Date: 20 Nov 2026
- Owner: dg-lead-architect
- Supersedes: the chain order in ADR-0005. Amends ADR-0008 decision 1 for the Space only.
- Related: ADR-0005, ADR-0008, `app/adapters/factory.py`, `scripts/deploy_space.py`, `docs/deploy.md`

## Context

ADR-0005 put the free OpenRouter models first and Groq last. The WP-3-geneval probe on 19 Nov showed that order failing in practice: or-gemma returned upstream 429s (0/5 answered), or-nemotron timed out, and or-free answered in the wrong language. groq-oss (`openai/gpt-oss-120b`) answered every probe within the TTFT budget. The user decided in session 4: Groq first.

Separately, ADR-0008 and PLAN section 10 assumed the Space builds the `Dockerfile` and starts uvicorn. The deployed Space is a Gradio-SDK Space. `scripts/deploy_space.py` uploads the repo with a generated `main.py` and `requirements.txt`. That `main.py` sets the runtime env (thread caps, cache paths, `RATE_LIMIT_XFF_HOP=last`) and mounts the same FastAPI app.

## Decision

1. The default chain (`LLM_CHAIN` empty) is, in order: `groq-oss`, `or-gemma`, `or-free`, `groq-qwen`. `LLM_CHAIN` (JSON) overrides it; or-nemotron stays available only through that override. Breaker, failover before the first token, and the quota ledger from ADR-0005 are unchanged. `end.provider` and `end.model` keep labelling which provider answered.
2. The HF Space runs the Gradio-SDK wrapper generated by `scripts/deploy_space.py`, not the `Dockerfile`. It is still one process and one event loop, so ADR-0008's state model holds. The `Dockerfile` stays the local and portable deploy path (`docker compose`), and must keep the same env defaults.
3. The Space requirements loosen pydantic to `>=2.11.10,<=2.12.5` for gradio compatibility. CI tests on 2.14.3. This gap is recorded, not closed (WP-5 MN-3).

## Alternatives rejected

- **Keep OpenRouter first.** Meets the letter of "free OpenRouter model" but most live answers would fail over or degrade, and every failover spends TTFT budget.
- **Docker-SDK Space.** Matches ADR-0008 literally, but the Gradio-SDK path was the one that deployed and stayed up within the time box.

## Consequences

- Every L0 record and almost every live answer comes from groq-oss. The free OpenRouter model is wired in and reachable as the second entry, but is not what users usually see. README and SUBMISSION must say this explicitly.
- Only groq-oss is measured as a generator (WP-5 E-7). The other three chain entries are unverified.
- Two deploy paths must stay in sync: the generated `main.py` env and the `Dockerfile`/`app/config.py` defaults. `RATE_LIMIT_XFF_HOP` is the example that drifted (fixed by making `last` the code default).
- The Space runs on a pydantic version that no test covers.

## Trade-off accepted

Reliable, fast answers from Groq over strict use of the free OpenRouter model as primary; and a deploy path that works on the Space over one that matches the Dockerfile exactly.
